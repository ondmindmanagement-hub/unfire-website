# Unfire OS · Evidence Runner Lab

**Status: isolated research prototype. Not a production task runner, model orchestrator, operating system service, live agent, or security attestation.**

This experiment answers the current engineering question in #247: can we complete a small deterministic task without confusing the *planning* of a task with verified work? Yes, for three allowlisted, pure operations in this in-memory simulation. No external APIs, subprocesses, file writes, credentials or account access are exposed by the runner.

## Verified lifecycle

`READY → CLAIMED → RUNNING → EVIDENCE_READY → VERIFIED`

Other allowed outcomes are `FAILED` and `CANCELLED`. `VERIFIED` is entered only after independent deterministic recomputation confirms the submitted output, the SHA-256 **checksum** matches, the lease still belongs to the same worker/generation, and all previous transitions were satisfied. Checksums demonstrate data consistency in this toy experiment, **not provenance, signed attestation, trusted worker identity or external work**. All tasks are explicitly synthetic, and the verifier and worker run in the same local process.

## Controls implemented

- Whitelisted pure operations only: `math.sum`, `text.uppercase`, `text.wordCount`.
- Explicit approval required for protected synthetic tasks; stale task revision blocks reuse.
- Dependencies unlock only after a predecessor reaches `VERIFIED`.
- Exclusive claim with bounded lease and a monotonically increasing, per-task fencing generation.
- Expiration erases unverified evidence; no more than three claims per task; cancelled work cannot restart.
- A global idempotent STOP cancels all nonterminal tasks, preserves already-verified results, and blocks future registration/claims.
- Strict task/evidence shapes, bounded inputs and task counts; audit transitions log IDs/states/revisions, not input payloads.
- Cloned task snapshots prevent callers from mutating internal state through a returned object.

## Run exactly

Node.js v22+ with only standard built-in modules:

```sh
node --test experiments/unfire-execution-lab/runner.test.mjs
node experiments/unfire-execution-lab/demo.mjs
```

## Out-of-scope and deployment blockers

This is **not asynchronous or concurrent**. It does not provide secure identities, externally signed evidence, cross-process leases, durable state, restart recovery, trusted clocks, cancellation of real worker processes, sandboxing or permission isolation. The in-memory generation is a *logic check*, not a distributed fencing token enforced by real storage. Approval is deliberately a local boolean, not user identity verification. Hashes can be regenerated by the same process and are not proof that a person or AI worker really executed anything. The demo's three tasks execute sequentially.

Before a real-worker adapter, separately design and test: isolated worker identities and OS-level capabilities, a durable append-only evidence store, crash/replay and idempotency recovery, trusted monotonic time, secret redaction, verifiable approval provenance, independently scoped auditors, real STOP/rollback, adversarial injection tests and reproducible one-vs-many agent performance benchmarking. Reject any use that transforms an offline checksum into a claim of trustworthy remote completion.
