# Unfire — App Store taxonomy and web catalogue
**Prepared:** 24 October 2026 · **Status:** recommended classification, **not** a record of changes saved to App Store Connect.

## Separation of controls
Apple's **More by Omar Baró** page is generated by Apple. Developers cannot create named subgroups on that profile or choose its manual order. Each app can have a primary and secondary **App Store category**, and those categories influence discovery, not the layout of that developer page. For macOS, align the Xcode app category with the Store primary category. Apple category rules: https://developer.apple.com/app-store/categories/ and https://developer.apple.com/help/app-store-connect/reference/app-information/app-information .

The owned website `/apps/` is the controllable catalogue. It uses four existing product families and orthogonal filters for purpose and physical device; it does **not** suggest that apps with different platforms are identical.

## Rules for every release
1. Identify correct app record, bundle ID, target platforms and actual state in App Store Connect; never infer approval from GitHub, a screenshot or another app's status.
2. Compare each existing primary and secondary App Store category to actual app function; do not set irrelevant categories merely to improve ranking.
3. For Mac, make Xcode's App Category consistent with the App Store primary. Treat changes to Xcode project as a separate coordinated code change.
4. Verify display name, subtitle, keywords, English/Spanish localization, screenshots, privacy disclosures, support URL, review status, link, legal usage of marks, accessibility and availability per device.
5. Publish only after correct app review/release checks. Revalidate the owned web status separately; never say review in progress without a fresh source.
6. Keep all public company wording as an independent initiative unless formation is confirmed. Preserve genuine company imagery; never put a founder photo into game/product art.
